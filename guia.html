Segunda mitad: argumentación (elige 2 y prepara las 4)

¿Por qué valido response.ok?

fetch solo falla si no hay red. Un 404 o un 500 llegan como respuestas normales. Si no los reviso, intentaría leer datos que no existen. Validarlo me deja dar un mensaje claro y distinguir "no existe" de "se rompió".

¿Por qué el spinner va en finally?

finally corre siempre. Si lo ocultara al final del try, un error saltaría al catch y el spinner se quedaría girando. Se puede comprobar moviéndolo: con "pikachuu" el spinner se queda pegado.

¿Por qué una función adaptadora?

La API tiene su estructura (name, sprites.front_default, types[].type.name) y mi app la suya. El adaptador traduce en un solo lugar, por eso crearTarjeta y render no cambiaron desde el Lab 09 aunque los datos ahora vienen de internet.

¿Por qué 404 devuelve null y no un error?

Porque la búsqueda funcionó, solo no hay resultado. Así separo "no hay nada" (aviso neutro) de "algo se rompió" (mensaje rojo con Reintentar). Cada caso le dice algo útil al usuario.

Paso 5

Conceptos en modo chimp

34 conceptos, cada uno con una explicación simple, un ejemplo de TU código y la pregunta trampa que te pueden hacer. Filtra por laboratorio.

Lab 09

Template literal

Un texto con comillas invertidas ` donde metes variables con ${ }. Como rellenar los espacios en blanco de un formulario.

const numeroDex = numero ? `Nº${String(numero).padStart(3, "0")}` : "";
¿Qué diferencia hay con las comillas normales?

Con backticks puedo meter variables con ${} y escribir varias líneas. Con comillas normales tendría que concatenar con +.

Lab 09

Destructuring de objeto

Sacar varias propiedades de un objeto a variables en una sola línea. Es abrir la mochila y poner cada cosa en la mesa.

const { nombre, imagen, tipos, numero } = pokemon;
// es lo mismo que:
// const nombre = pokemon.nombre; const imagen = pokemon.imagen; ...
¿Para qué sirve?

Para no repetir pokemon. todo el tiempo. El código queda más corto y se lee mejor.

Lab 09

Destructuring de array (con valor por defecto)

Igual que el de objeto, pero por posición. Tomo el primer elemento del array y, si no existe, uso un valor de respaldo.

const [principal = "desconocido"] = tipos ?? [];
// tipos = ["fire", "flying"]  →  principal = "fire"
¿Y si tipos no existe?

El ?? [] me da un array vacío, así que principal toma el valor por defecto "desconocido" y no se rompe.

Lab 09

Spread ...

Los tres puntos "vacían" un array (o un Set) dentro de otro. Como volcar una bolsa de caramelos en un tazón nuevo.

const tipos = [...new Set(pokedex.flatMap(p => p.tipos))].sort();
// en el Lab 09: const ampliada = [...pokemonLocal, nuevo];
¿Por qué [...new Set(...)]?

Un Set elimina repetidos, pero no es un array. Con el spread lo convierto en array para poder usar .sort() y .forEach().

Lab 09

Optional chaining ?.

"Si existe, entra; si no, devuelve undefined en vez de explotar". Evita el error clásico Cannot read properties of undefined.

imagen: data.sprites?.front_default ?? "https://via.placeholder.com/96?text=?",
const badges = tipos?.map(badgeTipo).join("") ?? "";
¿Qué pasa sin el ?.?

Si data.sprites no existiera, data.sprites.front_default lanzaría un error y la tarjeta no se dibujaría.

Lab 09

Nullish coalescing ??

"Si lo de la izquierda es null o undefined, usa lo de la derecha". Es el plan B.

const img = imagen ?? "https://via.placeholder.com/96?text=?";
const etiqueta = nombresStats[nombre] ?? nombre;
¿Por qué ?? y no ||?

|| también reemplaza 0 y "". ?? solo reemplaza null o undefined. Si una estadística valiera 0, con || la perdería.

Lab 09

Patrón render

La receta para dibujar una lista: 1) limpiar el contenedor, 2) recorrer los datos, 3) crear un nodo por cada dato, 4) insertarlo. La pantalla es un reflejo de los datos.

function render(lista) {
  contenedor.innerHTML = "";        // 1. limpia
  lista.forEach(function (pokemon) { // 2. recorre
    const tarjeta = crearTarjeta(pokemon); // 3. crea
    contenedor.appendChild(tarjeta);       // 4. inserta
  });
}
¿Por qué primero limpias?

Si no limpio, cada vez que llamo a render se agregarían tarjetas encima de las anteriores y tendría duplicados.

Lab 09

createElement, appendChild, append, replaceChildren

Las "manos" del DOM: createElement fabrica una etiqueta, appendChild/append la pegan dentro de otra y replaceChildren borra lo que había y pone lo nuevo.

const boton = document.createElement("button");
tarjeta.appendChild(boton);
aviso.append(titulo, ayuda);          // varios a la vez
contenedor.replaceChildren(aviso);    // limpia + pone
¿Diferencia entre appendChild y append?

appendChild recibe un solo nodo. append recibe varios, e incluso texto.

Lab 09

innerHTML vs textContent

innerHTML interpreta el texto como HTML (crea etiquetas). textContent lo pone como texto plano, sin interpretar nada.

articulo.innerHTML = `<h2>${nombre}</h2>`;                 // datos de la API
titulo.textContent = `🔍 No se encontró "${nombre}"`;  // texto que escribió la persona
¿Por qué en un lado innerHTML y en otro textContent?

Las tarjetas se arman con datos de la PokeAPI. Lo que escribe la persona en el buscador lo muestro con textContent, así si alguien escribe <img onerror=...> se ve como texto y no se ejecuta (eso se llama ataque XSS).

Lab 09

Eventos

addEventListener es decirle a un elemento: "cuando pase X, ejecuta esta función". X puede ser click, keydown, input…

buscador.addEventListener("keydown", function (event) {
  if (event.key === "Enter") boton.click();
});
¿Qué es event?

Un objeto con información de lo que pasó. event.key dice qué tecla se presionó.

Lab 09

Métodos de array (repaso M2)

map transforma cada elemento, filter se queda con los que cumplen, some pregunta "¿hay alguno?", forEach recorre sin devolver nada, reduce acumula en un valor, join une en un texto, includes pregunta "¿está?".

pokedex.filter(p => p.tipos.includes(tipoActivo))   // solo los del tipo
pokedex.some(p => p.nombre === pokemon.nombre)      // ¿ya lo tengo?
stats.reduce((suma, s) => suma + s.valor, 0)        // total
¿Diferencia entre map y forEach?

map devuelve un array nuevo con los resultados. forEach solo recorre y no devuelve nada.

Lab 09

Arrow function =>

Una forma corta de escribir funciones. p => p.nombre es "dame un p y te devuelvo su nombre".

p => p.nombre !== pokemon.nombre
// es lo mismo que:
// function (p) { return p.nombre !== pokemon.nombre; }
¿Cuándo uso arrow?

Sobre todo cuando paso una función como argumento: .map(...), .filter(...), .some(...).

Lab 10

API, endpoint y JSON

Una API es un servidor que te da datos si le pides una URL (el endpoint). Los datos viajan como texto en formato JSON, que se parece a un objeto de JavaScript.

https://pokeapi.co/api/v2/pokemon/pikachu
// responde: { "name": "pikachu", "id": 25, "sprites": {...}, "types": [...], "stats": [...] }
¿El JSON es lo mismo que un objeto JS?

No. El JSON es texto. Con response.json() lo convierto en un objeto de JavaScript que sí puedo usar.

Lab 10

Asincronía

Pedir algo por internet tarda. JavaScript no se queda congelado esperando: sigue con lo demás y reacciona cuando llegan los datos. Es como pedir delivery: no te quedas mirando la puerta, sigues viendo tele.

console.log("1. pido los datos…");
fetch(url).then(() => console.log("3. llegaron"));
console.log("2. sigo trabajando");
// imprime 1 → 2 → 3
¿Por qué sale 1, 2, 3 y no 1, 3, 2?

Porque fetch es asíncrono: JavaScript no espera la respuesta, imprime el 2 y recién cuando llegan los datos ejecuta lo del .then.

Lab 10

Promesa

Un "ticket" por un dato que llegará después. Tiene 3 estados: pending (esperando), fulfilled (llegó) o rejected (falló).

console.log(fetch(url));  // Promise { <pending> }
¿Qué devuelve fetch?

No devuelve los datos: devuelve una Promesa de esos datos.

Lab 10

fetch + response.json()

Son dos esperas: fetch espera la respuesta del servidor y response.json() espera a leer el cuerpo y convertirlo en objeto.

const response = await fetch(`https://pokeapi.co/api/v2/pokemon/${idONombre}`);
return response.json();
¿Por qué hay dos await o dos .then?

Porque leer el cuerpo de la respuesta también tarda y también devuelve una Promesa.

Lab 10

Función adaptadora

Un "traductor". La API habla su idioma (name, sprites.front_default, types[].type.name) y mi app habla el suyo (nombre, imagen, tipos). El adaptador traduce en un solo lugar.

tipos: data.types.map(t => t.type.name)
// [{ type: { name: "fire" } }, { type: { name: "flying" } }]  →  ["fire", "flying"]
¿Por qué no usar los datos de la API directo?

Porque así crearTarjeta y render no cambiaron desde el Lab 09. Si la API cambiara, solo arreglo el adaptador.

Lab 10

Promise.all

Lanza varios pedidos a la vez y espera a que TODOS terminen. Es mandar a 6 amigos a comprar a la vez en vez de ir tú 6 veces.

const datos = await Promise.all(nombres.map(obtenerPokemon));
¿Y si uno de los 6 falla?

Promise.all falla completo (se rechaza) con el primer error. Por eso todo está dentro de try y, si falla, sale "No se pudo cargar la Pokédex." con Reintentar.

Lab 11

async / await

Otra forma de escribir Promesas que se lee de arriba a abajo. await pausa la función hasta que la Promesa se resuelva y te da el valor directo. Es "azúcar sintáctico": lo mismo que .then, pero más fácil de leer.

// con .then (C10)
fetch(url).then(r => r.json()).then(data => ...);
// con await (C11)
const response = await fetch(url);
const data = await response.json();
¿Puedo usar await en cualquier lado?

Solo dentro de una función marcada con async. Y una función async siempre devuelve una Promesa.

Lab 11

Parámetro de ruta vs de consulta

La ruta dice qué recurso quieres (/pokemon/pikachu). La consulta, después del ?, dice cómo lo quieres (?limit=12&offset=24).

fetch(`https://pokeapi.co/api/v2/pokemon/${idONombre}`)                    // ruta
fetch(`https://pokeapi.co/api/v2/pokemon?limit=12&offset=${offset}`)   // consulta
¿Qué hacen limit y offset?

limit = cuántos traer (12). offset = desde cuál empezar. Subiendo el offset de 12 en 12 obtengo la siguiente página: eso es paginación.

Lab 11

Estado de la app

Las variables que guardan "cómo está la app ahora": pokedex (mi colección), tipoActivo (el filtro elegido) y offset (por qué página voy). Si cambia el estado, vuelvo a dibujar.

let pokedex = [];
let tipoActivo = "todos";
let offset = 0;
¿Por qué let y no const?

Porque las reasigno: pokedex = datos.map(...), pokedex = pokedex.filter(...), offset += 12. Una const no se puede reasignar.

Lab 11

No duplicar con .some()

Antes de agregar, pregunto "¿ya hay alguno con este nombre?". Si no hay, lo agrego.

if (!pokedex.some(p => p.nombre === pokemon.nombre)) {
  pokedex.push(pokemon);
}
¿Por qué no pokedex.includes(pokemon)?

Porque includes compara si es el MISMO objeto en memoria. Si busco charizard dos veces obtengo dos objetos distintos con los mismos datos. Por eso comparo por nombre.

Lab 11

Explorar el JSON

La API te da muchísimo más de lo que usas. Tu trabajo es navegarlo y sacar lo que sirve: data.id para el número y data.stats para las estadísticas.

stats: data.stats.map(s => ({ nombre: s.stat.name, valor: s.base_stat }))
// [{ base_stat: 78, stat: { name: "hp" } }, ...] → [{ nombre: "hp", valor: 78 }, ...]
¿Por qué los paréntesis en => ({ ... })?

Para que JavaScript entienda que devuelvo un objeto. Sin paréntesis pensaría que las llaves son el cuerpo de la función.

Lab 12

try / catch / finally

try: "intenta esto". catch: "si algo falla, haz esto en vez de romperte". finally: "y pase lo que pase, haz esto al final".

try {
  const pokemon = await buscarPokemon(nombre);
  ...
} catch (error) {
  mostrarError(texto, ...);
} finally {
  spinner.classList.add("hidden");   // SIEMPRE
}
¿Por qué el spinner se oculta en finally?

Porque finally corre con éxito y con error. Si lo ocultara al final del try, un error saltaría al catch y el spinner se quedaría girando para siempre.

Lab 12

throw new Error

Lanzar tu propio error con un mensaje claro. El throw corta el try y salta directo al catch.

if (!response.ok) {
  throw new Error(`La PokeAPI respondió con un error (${response.status}). Intenta de nuevo.`);
}
¿Qué recibe el catch?

El objeto Error que lancé. Con error.message leo el texto que escribí.

Lab 12

response.ok y response.status

Ojo: fetch SOLO falla si no hay red. Un 404 (no existe) o un 500 (servidor caído) llegan como respuestas "normales". Hay que revisarlas a mano. ok es true solo entre 200 y 299.

if (response.status === 404) return null;   // no existe
if (!response.ok) throw new Error(...);      // 500, 503…
¿Por qué hay que validar response.ok?

Porque si no lo hago, con un 404 intentaría leer un JSON que no existe y la app fallaría de forma confusa. Validarlo me deja dar un mensaje claro.

"No encontrado" no es un error

Si busco pikachuu la búsqueda funcionó: simplemente no hay resultado. Por eso con 404 devuelvo null y muestro un aviso neutro, distinto del error rojo de "sin conexión".

const pokemon = await buscarPokemon(nombre);

  mostrarNoEncontrado(nombre);   // aviso neutro

  mostrarResultado(pokemon);

¿Por qué separar los dos casos?

Porque son situaciones distintas para el usuario: "escribiste mal el nombre" no es lo mismo que "se cayó tu internet". Así cada uno ve un mensaje que le sirve.

Detectar "sin red" con instanceof TypeError

Cuando no hay internet, fetch lanza un TypeError en todos los navegadores. El texto cambia según el navegador (Chrome: "Failed to fetch", Safari: "Load failed"), por eso reviso el TIPO de error y no el texto.

const texto = error instanceof TypeError
  ? "Algo salió mal. Revisa tu conexión."
  : error.message;
¿Qué hace el ? :?

Es un if corto (operador ternario): si es TypeError, usa el primer texto; si no, usa el mensaje del error.

async function obtenerPokemon(idONombre) {
  const response = await fetch(`https://pokeapi.co/api/v2/pokemon/${idONombre}`);

  // Logro: "no existe" no es un fallo de la app → devolvemos null (resultado vacío)
  if (response.status === 404) {
    return null;
  }

  // HU2: fetch NO falla por un 404 ni un 500, hay que revisarlo con response.ok
  if (!response.ok) {                                    // 500, 503, etc.
    throw new Error(`La PokeAPI respondió con un error (${response.status}). Intenta de nuevo.`);
  }

  return response.json();
}

En cristiano

  1. async: devuelve una Promesa y permite usar await.
  2. await fetch(...): espera la respuesta. Sirve con nombre ("pikachu") o número (25).
  3. Si es 404 → return null: no existe, no es un error.
  4. Si no es ok (500, 503…) → throw new Error(...): salta al catch de quien la llamó.
  5. Si todo bien → response.json(): los datos como objeto.

Async¿Qué es la asincronía y por qué importa en tu app?

Pedir datos por internet tarda. JavaScript no se congela esperando: sigue trabajando y reacciona cuando llegan. Por eso la página no se traba mientras carga la Pokédex.

Async¿Qué devuelve fetch?

Una Promesa: un "ticket" por la respuesta que llegará después. No los datos directamente.

Async¿Cuál es la diferencia entre .then y async/await?

Hacen lo mismo. async/await es azúcar sintáctico: se lee de arriba a abajo como código normal. En el Lab 11 reescribí la carga del Lab 10 con await y el resultado fue idéntico.

Async¿Qué pasa si olvido el await antes de fetch?

response sería una Promesa y no la respuesta. response.status daría undefined y todo lo que sigue fallaría.

Async¿Por qué usas Promise.all?

Para pedir los 6 Pokémon a la vez. En paralelo tarda lo que tarde el más lento; uno por uno tardaría la suma de todos.

AsyncSi uno de los 6 pedidos de Promise.all falla, ¿qué pasa?

Promise.all se rechaza completo. Entra al catch de cargarPokedex y aparece "No se pudo cargar la Pokédex." con Reintentar.

Errores¿Por qué validas response.ok?

Porque fetch solo falla si no hay red. Un 404 o un 500 llegan como respuestas normales. Si no los reviso, intentaría leer datos que no existen y la app fallaría de forma confusa.

Errores¿Por qué ocultas el spinner en finally?

Porque finally corre siempre, con éxito o con error. Si lo pusiera al final del try, un error saltaría directo al catch y el spinner se quedaría girando.

Errores¿Qué diferencia hay entre devolver null y lanzar un error?

null significa "funcionó pero no hay resultado" (404). throw significa "algo se rompió" (500, sin red). Así muestro un aviso neutro o un error rojo según el caso.

Errores¿Cómo sabes que el error es por falta de internet?

Cuando no hay red, fetch lanza un TypeError en todos los navegadores. Lo reviso con error instanceof TypeError y no por el texto, porque el texto cambia (Chrome dice "Failed to fetch", Safari "Load failed").

Errores¿Qué hace throw new Error("...")?

Crea un error con mi mensaje y corta el try: salta directo al catch, donde leo el texto con error.message.

Errores¿Cómo funciona el botón Reintentar?

mostrarError recibe una función como segundo argumento (un callback) y la asigna al clic del botón. Así un solo botón repite la búsqueda, la carga inicial o "Cargar más".

Render¿Qué es el patrón render?

Limpiar el contenedor, recorrer los datos, crear un nodo por cada dato e insertarlo. La pantalla es un reflejo de los datos: si cambian los datos, vuelvo a llamar a render.

Render¿Por qué tienes una función adaptadora?

La API usa su estructura (name, sprites.front_default, types[].type.name) y mi app usa la suya (nombre, imagen, tipos). El adaptador traduce en un solo lugar, por eso crearTarjeta y render no cambiaron desde el Lab 09.

Render¿Diferencia entre innerHTML y textContent?

innerHTML interpreta HTML; textContent pone texto plano. Lo que escribe la persona lo muestro con textContent para que no se ejecute código (XSS).

Render¿Por qué crearTarjeta devuelve el nodo en vez de insertarlo?

Para reusarla: la rejilla le agrega Quitar y el resultado de búsqueda le agrega las barras y Capturar.

JS¿Qué es el destructuring?

Sacar propiedades de un objeto (o elementos de un array) a variables en una línea: const { nombre, imagen } = pokemon.

JS¿Qué hacen ?. y ???

?. entra a una propiedad solo si existe (si no, da undefined sin romper). ?? da un valor de respaldo si lo de la izquierda es null o undefined.

JS¿Por qué let pokedex y no const?

Porque la reasigno: al cargar (pokedex = datos.map(...)) y al quitar (pokedex = pokedex.filter(...)).

JS¿Cómo evitas duplicados al capturar?

Con pokedex.some(p => p.nombre === pokemon.nombre): si ya hay uno con ese nombre, no lo agrego.

JS¿Qué hace [...new Set(pokedex.flatMap(p => p.tipos))]?

flatMap junta todos los tipos en un array, Set quita repetidos y el spread lo vuelve a convertir en array.

API¿Qué diferencia hay entre parámetro de ruta y de consulta?

Ruta: qué recurso (/pokemon/pikachu). Consulta: cómo lo quiero (?limit=12&offset=24).

API¿Cómo funciona "Cargar más"?

Pide ?limit=12&offset=N, recibe 12 nombres con su URL, pide el detalle de los 12 en paralelo, agrega los que no tenía y sube el offset en 12 para la próxima página.

API¿Por qué puedes buscar por número?

Porque la API acepta /pokemon/25 igual que /pokemon/pikachu. El mismo código sirve para los dos.
